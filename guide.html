0. 先建立一个正确的心智模型

很多人第一次接触 EtherCAT，会把它想成"更快的 Modbus"：主站挨个问从站"你的输入是多少"。 不是的。

EtherCAT 的工作方式是：

  1. 主站每个周期只发一个以太网帧；
  2. 帧里装着若干 EtherCAT PDU（datagram），每个 PDU 指向一段地址；
  3. 帧沿着网络依次穿过每个从站，从站用硬件（ESC）在转发的同时就地读写自己那段内存；
  4. 帧绕一圈回到主站，所有从站的输入都已经在帧里了。

所以它是一个在环上循环的共享内存，而不是请求-响应式总线。 这带来三个直接后果：

  • 周期时间几乎与从站数量线性相关（每站几百纳秒），而不是往返次数；
  • 一个 PDU 可以同时命中多个从站（逻辑寻址），实现"一帧写遍全网"；
  • 主站必须在发帧前把整张过程映像组好，发帧后整张解析——这决定了主站软件的结构。

〔ETG.1000.4 §4.7 / §5.3〕

1. 三层协议栈

EtherCAT 只用了 OSI 的三层。这个"只用三层"的设计是它确定性的根源： 没有 IP 路由、没有 TCP 重传、没有应用层会话，全部压进以太网帧的一个 EtherType。

OSIEtherCAT规范主要职责
L7 应用层ALETG.1000.5 / .6对象字典、PDO、SDO、ESM 状态机、邮箱协议
L2 数据链路层DLLETG.1000.3 / .4帧与 PDU 编码、寻址、FMMU、SyncManager、WKC、DC 寄存器
L1 物理层PHYETG.1000.2100BASE-TX（MII）与 E-Bus（LVDS）、编码、端口

再往上，设备行规（DS402 驱动、ETG.5001 IO-Link、FSoE 安全）才定义"这些字节代表什么物理量"。

1.1 物理层：两种介质

  • 100BASE-TX：标准以太网 PHY，RJ45，全双工，但 EtherCAT 只用其物理层，不用 CSMA/CD。
  • E-Bus：ETG 定义的 LVDS 点对点背板总线，用于模块化从站（耦合器 + 端子模块），延迟更低、成本更低。
  • 端口数可以是 2（线型）、3/4（分支或冗余）。

一个常被忽略的点：从站不是"收完整个帧再处理"，而是边收边转发（cut-through）。 这就是为什么单站延迟可以做到亚微秒级，也是为什么帧不能被分片、不能走需要重组的链路。

〔ETG.1000.2 §9–10〕

1.2 数据链路层：一帧到底是什么

一个 EtherCAT 帧 = 标准以太网头 + EtherType 0x88A4 + EtherCAT 帧头 + 1..n 个 PDU + FCS。

EtherCAT 帧头（2 字节）：

bit  15..11   10..0
     res      Length         —— Length = 其后 ECAT 内容长度（不含这 2 字节），11 位，≤2047

实际上这 2 字节里还有 4 位 Type（0x1 = EtherCAT PDU，0x4 = 网络变量，0x5 = 邮箱），

所以布局是：Length:11 | Reserved:1 | Type:4。

Datagram Header（10 字节），这是全站最该背下来的一张表：

偏移字段宽度含义
+0CMD8 bit服务命令，见下表
+1IDX8 bit主站本地请求号，从站不得修改
+2ADP / ADR16 bit位置寻址（递减）或节点地址（站地址/别名）
+4ADO16 bit从站内部物理地址（寄存器/内存）
+6LEN \res \C \NEXT11+3+1+1数据长度、保留、已绕环、后面还有 PDU
+8IRQ16 bit外部事件掩码
+10DATALEN 字节数据区
+10+LENWKC16 bit工作计数器

逻辑寻址时，ADP+ADO 这 4 个字节合并成 32 位 ADR（逻辑地址），所以头部仍然是 10 字节。

寻址方式读写读写

〔ETG.1000.4 §5.4〕

1.4 三种寻址方式的生命周期

上电 / INIT ── APRD, APWR（按物理位置数第几个）──> 读 SII、分配站地址
配置 / PREOP ── FPRD, FPWR（按已分配的站地址）──> 写 SM/FMMU/对象字典
运行 / OP   ── LRD, LWR, LRW（32 位逻辑地址）──> 过程数据交换

位置寻址依赖"当前物理顺序"，插拔一个从站就会错位——所以它只用于上电枚举。 一旦站地址分配完成，后续全部用节点寻址或逻辑寻址，与物理顺序解耦。

〔ETG.1000.3 §4.8 / ETG.1500 §5.5〕

2. 一次周期通信的完整路径

以 5 个从站、1 ms 周期为例：

主站 CPU
  │ ① 组帧：把输出过程映像拷进 LRW 的数据区
  │ ② 发送：网卡把帧推上线（100 Mbit/s，1 字节 = 80 ns）
  ▼
ESC #0 ──► ESC #1 ──► ESC #2 ──► ESC #3 ──► ESC #4
  │           │           │           │           │
  │ 每站：查 FMMU → 命中则把帧里的数据写入物理内存，
  │       或把物理内存的数据填进帧；WKC += 1（读写都做则 +2）
  ▼
帧沿环回到主站
  │ ③ 校验 WKC 是否等于期望值
  │ ④ 解帧：把数据区拷回输入过程映像
  ▼
应用任务（PLC / 运动控制）

时间都花在哪： 帧上线（帧长 × 80 ns）+ 每站转发（0.3–0.6 µs）+ 线缆（5 ns/m）+ 主站组帧/解帧。 一个 128 字节的帧、10 个从站，典型在 15–20 µs 量级；1 ms 周期下占用不到 2%。 真正的瓶颈往往在主站软件（拷贝、锁、调度），而不是网络。

〔ETG.1500 §5.4 / 各厂商 ESC 数据手册〕

2.1 工作计数器 WKC：主站的签收单

  • 读命中 +1，写命中 +1，读写都命中 +2；
  • 计数单位是"命中次数"，不是"从站个数"：一个从站有 2 个 FMMU 落在该逻辑地址范围，就 +2；
  • 主站比对 WKC 与期望值，不等就说明：从站掉线 / 地址错 / FMMU 未映射 / 数据长度不匹配。

注意 WKC 只证明"有从站处理了"，不证明"数据是对的"。数据正确性要靠 AL Status、CRC 计数、 以及应用层的合理性检查。

〔ETG.1000.4 §5.4.1.1〕

3. 状态机：为什么上电后不能立刻交换过程数据

EtherCAT 从站有一个五态状态机（ESM）。主站写 AL Control (0x0120) 请求状态， 从站把当前状态放在 AL Status (0x0130)，出错时把原因放进 AL Status Code (0x0134)。

        ┌──────────┐
        │   INIT   │◄──────────────┐
        └────┬─────┘               │
             │ 邮箱配好               │ 任意错误 / 强制复位
        ┌────▼─────┐               │
        │  PREOP   │───────────────┤
        └────┬─────┘               │
             │ SM2/SM3 + FMMU 配好   │
        ┌────▼─────┐               │
        │  SAFEOP  │───────────────┤
        └────┬─────┘               │
             │ 输出就绪               │
        ┌────▼─────┐               │
        │    OP    │───────────────┘
        └──────────┘

  INIT ──► BOOT（仅 FoE 固件下载）
状态AL Control 值邮箱过程数据典型动作
INIT0x01未配置不可用读 SII、分配站地址
PREOP0x02可用不可用SDO 配置、PDO 映射
SAFEOP0x04可用输入有效，输出保持安全值验证输入、建立 DC 同步
OP0x08可用输入输出全部有效正常生产
BOOT0x03仅 FoE不可用固件升级

规则：向上迁移需要无错误；任何 AL 错误会把状态退回，并阻止进入 OP。 每次迁移都是"请求 → 从站执行 → 状态确认"，主站必须轮询 AL Status 直到看到目标状态。

4. 邮箱：配置期怎么说话

运行期的过程数据是"广播式"的；配置期需要"点对点、可靠、可分段"的通道，这就是邮箱。

邮箱走 SyncManager 0（主→从）和 1（从→主）。每个报文 = 6 字节 Mailbox Header + 协议头 + 数据。

Mailbox Header（6 B）：Length(2) · Address(2) · Channel(6b)+Priority(2b) · Type(4b)+Cnt(3b)+Res(1b)。

Type 决定协议：

Type协议用途
0x01AoEADS over EtherCAT（Twincat/倍福体系）
0x02EoE把以太网帧隧道进 EtherCAT
0x03CoECANopen over EtherCAT（SDO / PDO / Emergency）
0x04FoE文件访问（固件升级）
0x05SoEServo Drive Profile（旧版伺服行规）

CoE 是最常用的。CoE 头 2 字节：Number:9 | Reserved:3 | Service:4， Service 0x02/0x03 是 SDO 请求/响应，0x01 是 Emergency。

4.1 SDO 的三种传法

  • Expedited：数据 ≤ 4 字节，直接塞在 SDO 头里，一次往返。
  • Segmented：数据更长时，先 Initiate 拿到总长度，再一段段传；Toggle 位交替用于发现丢包。
  • Complete Access：一次读写整个对象的所有子索引，减少往返；要求从站支持且字节布局连续。

4.2 PDO 与过程数据

PDO 是把对象"打包"进过程数据的方式：

  • 0x1C12（RxPDO 分配）/ 0x1C13（TxPDO 分配）决定哪些 PDO 参与交换；
  • 0x16xx / 0x1Axx 决定每个 PDO 里放哪些对象、什么顺序；
  • 主站按 ESI 里声明的顺序和位宽计算过程映像偏移，再把这些偏移配置进 FMMU。

这就是为什么 ESI、SII、固件里的对象字典必须完全一致：错一个字节，整段数据就错位。

〔ETG.1000.6 §5.6 / ETG.1500 §5.7〕

4.3 CoE 之外的三种邮箱协议

同一个邮箱通道，靠 Mailbox Header 的 Type 字段分流：

Type协议头长度关键结构典型用途
0x01AoE6 BPort + IndexGroup + IndexOffset倍福 ADS、路由
0x02EoE4 BFrameType/Port + FragmentNumber + CompleteSize + FrameNumber隧道以太网、Web/Modbus/TCP
0x03CoE2 BService + Index/SubIndexSDO/PDO/Emergency
0x04FoE2 BOpCode + Password/FileName/PacketNo固件与文件传输
0x0FSoE2 B + 可选长度IDN（16 位）SERCOS 伺服参数

EoE 把一整个以太网帧（去掉前导码、SFD、FCS）切进邮箱，按 32 字节为一个 block， 用 FragmentNumber / Offset 重组；最后一个分片把 LastFragment 置 1，可追加 4 字节时间戳。 它是"停等"式的，吞吐受邮箱大小和主站轮询周期限制。

FoE 只有六个操作码：Read(0x01) / Write(0x02) / Data(0x03) / Ack(0x04) / Error(0x05) / Busy(0x06)。 固件升级 = Write Request 打开文件 + 循环 Data/Ack；从站擦 Flash 时可用 Busy 拖住主站。 推荐在 BOOT 状态做，此时邮箱只允许 FoE。

SoE 沿用 SERCOS 的 IDN 参数模型（S-0-xxxx / P-0-xxxx），与 CoE 的 Index/SubIndex 是两套体系。 注意：本地 ETG 文档只定义了 SoE 作为邮箱协议的存在（Type=0x0F、AL Status Code 0x0045）， 报文的逐字节结构在 IEC 61800-7-204 里，不在 ETG.1000 里。

5. 分布式时钟：确定性的最后一公里

即使帧按时到达，各从站的本地晶振也会漂。DC 的目标是让所有从站的时钟对齐到同一个系统时间， 并由 SYNC0 产生本地同步脉冲。

5.1 三步

  1. 测传播延时：帧绕环，每个从站记录端口 0 与端口 1 收到 SOF 的时刻，差值写入 0x0980；

逐级累加得到每个从站相对参考时钟的延时。

  1. 写偏移：参考时钟把系统时间写进帧；其它从站用自己的本地时间减去帧里的系统时间，

把差值写入 0x0920。之后"系统时间 = 本地时间 − 偏移"。

  1. 持续补偿漂移：主站周期性用 ARMW/FRMW 读参考时钟的漂移值并"多写"给所有从站（0x0928），

微调每个从站的时钟速率。

5.2 参考时钟

默认是"第一个支持 DC 的从站"。如果拓扑变化或该从站被换掉，系统时间基准会变， 所有偏移需要重算。部分主站允许显式指定参考从站。

5.3 SYNC0 / SYNC1

DC 只对齐"时间"，真正的动作由 SYNC0（周期脉冲）和 SYNC1（可配相位）触发。 SYNC0 周期必须是主站周期的整数倍，否则每个周期都会出现相位跳变，表现为周期性抖动。

〔ETG.1000.4 §6.8 / ETG.1500 §5.13〕

6. 主站：ETG 只规定"至少做到什么"

ETG.1500 把主站能力压成两档：

  • Class A（标准主站）：完整命令集、IRQ、设备仿真、VLAN、多任务、帧重复、完整邮箱与 CoE、

EoE/FoE/SoE/AoE/VoE、DC 与连续传播延时测量。

  • Class B（最低集）：核心命令、ESM、基本 PDO、邮箱、CoE SDO、Emergency、EEPROM 访问。

超出两档的功能用 Feature Pack 描述（如冗余、热插拔）。选主站时，先看它声明了哪些 Class 与 Feature Pack， 再看它的实时性实现（是否在内核态、是否用专用网卡、是否支持 DC）。

主站软件通常分三层：

应用/PLC 任务
   │  读写过程映像（共享内存）
   ▼
主站核心：周期调度器（组帧/发帧/解帧/WKC 校验/状态机/邮箱路由/诊断）
   │
   ▼
网卡驱动（raw socket / 专用 MAC / FPGA）

7. 从站：两份身份证

7.1 ESI（XML，设计期）

ETG.2000 定义结构，ETG.2001 用例子解释语义。核心元素：

EtherCATInfo
├── Vendor (Id, Name)
└── Descriptions
    ├── Groups
    └── Devices
        └── Device (Physics)
            ├── Type (ProductCode, RevisionNo)
            ├── Name (多语言)
            ├── Info (Electrical, Mailbox Timeout)
            └── Profile
                ├── Dictionary (DataTypes, Objects)
                ├── Sm (SyncManager 定义)
                ├── TxPdo / RxPdo (含 Entry)
                ├── Fmmu
                └── Dc (OpMode, AssignActivate, Sync0/1)

7.2 SII（EEPROM，运行期）

主站上电时先读 SII，才能在还没有 ESI 的情况下知道"这台设备怎么配"。SII 以 16 位字编址：

  • 固定头：VendorId、ProductCode、Revision、Serial、硬件/软件版本、站别名、邮箱配置、CRC；
  • 之后按类别（Category）组织：Strings、General、FMMU、SyncManager、TxPDO、RxPDO、DC。

访问通过 ESC 的 0x0F00 EEPROM 接口。

7.3 一致性

ETG.7000.2 是官方测试记录（A1–A10 章），测试中心按它逐项打勾： ESI、CTT 协议测试、指示灯、显式设备识别、DC、行规、标记、互操作。 开发阶段就应该按它自测，而不是等送测才发现问题。

〔ETG.2000 / ETG.2010 / ETG.7000.2 / ETG.2200〕

8. 冗余、热插拔与 EtherCAT G

  • 线缆冗余：从站有 3–4 个端口，主站从两个方向发同一帧；断一处，帧从另一方向到达。

需要主站支持 Feature Pack "Redundancy"，并处理重复帧（C 位）。

  • 热插拔 / Hot Connect：允许运行中增删从站组；主站需要识别拓扑变化并重新配置该段，

对主站实现要求较高。

  • EtherCAT G：把物理层换成 1 Gbit/s（G）或 2.5/5/10 Gbit/s（G10），帧格式与协议不变，

适合高采样率视觉/测量场景。

〔ETG.1000.4 §5.3（C 位）/ ETG.1500 §5.4.3〕

9. 建议的学习路径

  1. 先跑交互页：帧解剖 → 网络实验室。建立"帧在环上走、从站就地读写"的直觉。
  2. 再读状态机：从站与状态机页。理解 INIT→PREOP→SAFEOP→OP 每一步在使能什么。
  3. 然后看设备描述：ESI/SII 页。理解设计期契约与运行期事实怎么对上。
  4. 最后抠时间：分布式时钟页。理解偏移、漂移、SYNC0。
  5. 回到规范：按规范地图逐条回查；ETG.1000.4 §5 与 ETG.1000.6 §5 是两本必须精读的。

10. 常见误解清单

误解事实
"EtherCAT 是请求-响应式总线"一帧穿过所有从站，从站就地读写；没有逐站请求
"从站收到帧才处理"ESC 边收边转发，处理与转发同时进行
"WKC 对就说明数据对"WKC 只证明有从站处理了，不证明数据内容正确
"站地址就是物理位置"站地址是主站分配的；物理位置只用于上电枚举
"DC 就是 NTP 对时"DC 是硬件时钟同步 + SYNC 脉冲，精度在纳秒级
"ESI 里写了就行"固件对象字典、SII、ESI 三者必须一致
"周期越短越好"受帧长、从站数、主站软件开销约束；先算预算再定周期
"EtherCAT 需要交换机"不需要；它是环/线型，从站自带转发
