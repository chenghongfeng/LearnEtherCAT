ETG.1500 · ETG.1000.5 §4.2.5 · ETG.1510

主站视角 MainDevice 到底做什么

主站不是“发命令的 PLC”，而是一个周期性的帧调度器 + 状态机驱动 + 邮箱路由器。 ETG 只规定了它至少要做到什么（Class A / B），没规定怎么实现。 下面把 ETG.1500 的能力矩阵、启动时序、周期时间预算和诊断对象拆开看。

1 · 主站在协议栈里的位置

周期路径

过程数据

每周期组一帧（或多个 PDU）：LRW 读输入 + 写输出，或拆成 LRD/LWR 两个 PDU。 帧在环上转一圈，WKC 回来校验。

ETG.1000.5 §4.2.5.2 Slave Handler

非周期路径

邮箱

SDO 读写、Emergency、FoE 固件、EoE 隧道都走邮箱（SM0/SM1）。 主站要负责分段、重传、超时与 abort code 解析。

ETG.1000.6 §5.6 / ETG.1500 §5.6

控制路径

状态与诊断

驱动每个从站的 ESM（写 AL Control、轮询 AL Status）、收集 WKC 错误、 读 AL Status Code 与诊断历史。

5 · 主站诊断对象 0x8nnn / 0x9nnn / 0xAnnn

ETG.1510 把“网络健康”变成主站对象字典里可读的对象，方便上位机统一采集： 0x8nnn 描述从站静态属性与链路，0x9nnn 是运行计数，0xAnnn 直接映射 ESC 的 AL 寄存器。 ETG.1510 §5.7–5.9

0x8nnn

从站属性与链路

:01Fixed Station Address
:03Name
:05–08Vendor / Product / Rev / Serial
:33–34Mailbox Out / In Size
:35Link Status
:37Flags
:38Port Physics
:40Diag History 支持
0x9nnn

运行计数

:01Station Address
:05–08身份四元组
:32DL Status Register

0x9nnn 与 0x8nnn 的差别是“可变/计数”语义，适合做趋势曲线。

0xAnnn

:02AL Control
:03Last AL Status Code
:04–05Link Conn. Status / Control
