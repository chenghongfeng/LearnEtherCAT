ESC 内部原理 一帧是怎么在“从站控制器”里被顺手处理的

ESC（EtherCAT SubDevice Controller）常被说成“EtherCAT 的网卡”，但它其实是一张内存图加几个状态机： 端口把帧送进 EPU，EPU 边转发边按地址搬运数据、给 WKC 记账、顺手盖上时间戳，结果落在 DPRAM 里等本地 MCU 来取。 这一页把芯片拆成十个方块，逐块对着寄存器、规范和一份可运行的软件 ESC 实现看。

1 · 为什么必须是硬件：on the fly 的时延账

标准以太网交换机的“存储转发”要先收完整帧、校验、再发出去。100 个从站串成线， 每个都这么做一遍，一帧就要走 100 次“收满 + 发送”。EtherCAT 的做法是边收边转： 帧头刚过去，EPU 就已经把这条 PDU 处理完了，帧体不需要在 ESC 里停留。

（按 100 Mbit/s 计）

每站转发延时取 300 ns。ET1100 数据手册 Table 91 给出的实测平均值：MII→MII 305 ns、 MII→EBUS 280 ns、EBUS→MII 170 ns、EBUS→EBUS 150 ns；KickCAT 软件 ESC 用的默认建模值 也是 forwarding_delay_{300ns}。帧时间 = 字节数 × 80 ns。

关键点：ESC 处理的是帧里的每一条 PDU，不是整个帧。一条 APRD 只有 10 字节头 + 数据， 帧头一过，EPU 就已经知道“这条跟我有关还是无关”。所以延时随从站数线性增长，而不是随帧长。

2 · 内部结构：十个方块

点任意方块看它在干什么、对应哪些寄存器、规范里在哪、以及 KickCAT 的软件 ESC 里是哪段代码。 数据通路是 端口 0 → 自动转发器 → EPU → DPRAM → PDI； FMMU / SM / DC / SII / 看门狗 都是挂在这条通路两侧的“功能单元”。

为什么端口 0 一定在“上游”？ ETG.2200 §3.2 把 ESC 的帧处理叫“环岛（roundabout）”： 帧从端口 0 进来，在 EPU 里只处理一次，然后从 1/2/3 出去；从下游回来的帧只经过转发器，不再进 EPU。 所以每个从站对同一条 PDU 只会计一次 WKC——这正是 WKC 能用来判断“谁没响应”的前提。

4 · 地址怎么匹配：三种寻址在 ESC 里的判定

PDU 头里的 32 位地址只有两种解释：物理（16 位站标识 + 16 位 ADO）或逻辑（32 位 ADR）。 物理再分位置寻址与节点寻址。下面三个从站位置固定、站地址固定、各有一段 FMMU 窗口，改参数看谁会被命中。

位置寻址的“减 1”发生在每一站，包括没被选中的站。主站要访问第 k 站，ADP 初值写成 −k 的补码（第 1 站就是 0xFFFF）； 帧每过一站 ADP 加 1，恰好加到 0 的那一站执行。ETG.1000.3 §4.8.3.2 的例子：访问第 10 站，起始值 −9。

5 · 内存地图：0x0000–0xFFFF

ESC 对外只有“一片 64 KB 的地址空间”。0x0000–0x0FFF 是寄存器（规范定义语义）， 0x1000 起是过程数据 RAM（大小由 0x0006 声明，0–60 KB）。点一段看它下面有哪些寄存器。

全部寄存器
一个容易踩的坑：DC 的接收时间在 0x0900–0x090F（四个端口各 32 位）， 系统时间是 0x0910，0x0928 是传输延时、0x092C 才是 PLL 误差。 EEPROM 接口在 0x0500，0x0F00 是数字 IO。 这些偏移在 ETG.1000.4 Table 31/33/37/60 与 ESC Datasheet §II §2.45–2.51 里逐条给出。

6 · SyncManager：两侧访问的闸门

DPRAM 是双口的，两侧都能读写，所以必须有人管“什么时候算写完”。SM 把内存切成一致区， 给每个区定方向、缓冲类型和“空/满”状态位。邮箱是最严格的一种：写到最后一个字节才算满，读到最后一个字节才算空。

SM0（主站 → 从站 邮箱） 空
ECAT 侧（主站）空闲
PDI 侧（本地 MCU）空闲

非法操作不会“覆盖”，而是返回失败让调用方下个周期再试——这正是邮箱不会撕裂的原因 （ETG.1000.4 §7.2）。

7 · DC 单元与 SYNC/LATCH

DC 的硬件部分只做三件事：锁存接收时刻、维护一份可被修正的系统时间、按周期输出 SYNC0/SYNC1。 测量与算法都在主站侧。下面是主站真正会写的那几笔（顺序取自 KickCAT 的 Bus::enableDC()）。

2逐站读回四个端口的时间0x0900 / 0x0904 / 0x0908 / 0x090C主站用相邻端口之差算出链路延时并累加

4写速度计数启动值0x0930复位控制环滤波器
5FRMW 反复投喂参考时间0x0910参考站读出系统时间，其余站写入并据此微调本地时钟

8 · 参考实现：KickCAT 的软件 ESC

KickCAT 仓库里有一份可以跑、可以调试的软件 ESC：EmulatedESC 实现寄存器、SM、FMMU、EEPROM 和 DC 时钟， EmulatedNetwork 按真实端口顺序把若干软件 ESC 连成拓扑。主站开发阶段不必接硬件。

它的“内存图”就是那个寄存器结构体

整个实现的核心技巧：寄存器访问 = 结构体偏移访问。因为结构体是 packed 的、字段顺序与地址顺序一致， read(0x0130, &v, 2) 直接就是 memcpy(&v, (uint8_t*)&memory_ + 0x130, 2)， 再叠加 SM 的访问权限检查。ECC 的“内存图”就这么一行代码落地了。

EPU 的核心：15 条命令的分发

// EmulatedESC.cc:479  processEcatRequest()
auto [position, offset] = extractAddress(header->address);
switch (header->command)
{
    case Command::APRD:
        if (position == 0) { processReadCommand(header, data, wkc, offset); }
        ++position;
        header->address = createAddress(position, offset);   // ADP += 1（等于“下一站再减 1”）
        break;

    case Command::FPRD:
        if (matchesConfiguredAddress(position)) { processReadCommand(...); }
        break;                                              // 地址匹配才动手，不动地址

    case Command::BRD:                                       // 广播：数据按位或进帧
        processBroadcastReadCommand(header, data, wkc, offset);
        ++position;
        header->address = createAddress(position, offset);
        break;

    case Command::LRW:  { processLRW(header, data, wkc); break; }   // 交给 FMMU
}

注意 APRD 里那句 header->address = createAddress(position, offset)： 从站不改“地址语义”，只是把 ADP 加 1 再写回帧。下一站看到的就少 1，减到 0 的那一站执行—— 这就是位置寻址的全部秘密（ETG.1000.4 §5.4.1.2）。

10 · 四个常见误解

“ESC 就是一张网卡”

网卡把帧交给主机协议栈；ESC 自己改帧——按地址搬运、加 WKC、打时间戳，然后把结果放进共享内存。 主机看到的永远只是“我的输入变了 / 我的输出该取走了”。

“每个从站都要 CPU 参与转发”

转发完全在硬件里。本地 MCU 只碰自己那几个 SM 缓冲区，帧从它旁边流过它也不会知道。 这也是为什么从站可以用一颗几块钱的 MCU 跑到 1 ms 周期。

“WKC 就等于从站数量”

WKC 是按命中次数加的：读 +1、写 +2。一条 LRW 命中一个从站就是 3，不是 1。 同一个从站被两个 FMMU 各命中一次，也会加两次（ETG.1000.4 §5.4.3.5）。

“0x0004 写着 16 就一定能用 16 个 FMMU”

那是“支持的实体数”，不是“可自由分配的窗口数”。邮箱、PDO 会占掉一部分， 而且 FMMU 与 SM 的可用组合受器件配置（IP 核参数）约束，选型时要一起看。
