ETG.1000.6 §5.3–5.6 · ETG.1020 §4

从站与状态机 ESM、AL 寄存器、邮箱与 SDO

EtherCAT 的“应用层”没有想象中复杂：一台从站就是一个状态机 + 一张对象字典 + 两条邮箱通道。 状态机决定“能不能交换过程数据”，对象字典决定“能交换什么”，邮箱负责“配置期怎么说话”。

1 · ESM：五个状态，一条主线

主站通过写 AL Control (0x0120) 请求目标状态，从站把当前状态放在 AL Status (0x0130)，出错时把原因放进 AL Status Code (0x0134)。 每次迁移都要“请求 → 确认”，并且只有无错误时才能向上走。 ETG.1000.6 Table 103（完整迁移表）

2 · 邮箱：6 字节头 + 协议头

邮箱走 SyncManager 0（主→从）和 1（从→主）。每个邮箱报文 = 6 B Mailbox Header + 协议头（CoE/EoE/FoE/SoE/AoE）+ 数据。Type 字段区分协议：0x03=CoE、0x01=AoE、0x02=EoE、0x04=FoE、0x05=SoE。 ETG.1000.6 §5.6 / Table 29

4 · PDO 与对象字典：数据到底放在哪

对象字典结构

Index (16 bit)   SubIndex (8 bit)   Value
0x1000           :00               Device Type
0x1018           :01..04           Vendor/Product/Rev/Serial
0x1C12           :01..n            RxPDO 分配
0x1C13           :01..n            TxPDO 分配
0x6000 / 0x7000  :01..n            厂商自定义输入/输出

0x1C12/0x1C13 决定“哪些 PDO 参与交换”，0x16xx/0x1Axx 决定“每个 PDO 里放哪些对象”。 主站必须在 PREOP 阶段完成这两级配置。

从对象到帧里的字节

对象 0x6000:01 (16 bit) ┐
对象 0x6000:02 (8 bit) ├─ PDO 0x1A00 ─ TxPDO 对象 0x6010:01 (32 bit) ┘
↓ 主站按 ESI 计算偏移
过程映像偏移 +0x0000 … +0x0006
↓ FMMU 映射
逻辑地址 0x1000 … 0x1006
↓ LRW PDU 数据区
帧内字节 [0]…[6]

这就是为什么 ESI 里的 PDO 顺序、位宽、对齐必须和固件里的对象字典完全一致——错一个字节，主站拿到的就是错位数据。
